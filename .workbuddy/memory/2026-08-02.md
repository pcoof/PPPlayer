## 修复 pywebview 启动卡死 (main.py)

**现象**: `uv run main.py` 启动后窗口卡死，日志报
`Error while processing main_window.native.AccessibilityObject.Bounds.Empty.Empty...`（无限递归）。

**根因**: pywebview 在页面加载后会用 `dir()` + `getattr()` 遍历 `js_api` 对象（此处为 `PlayerWindow`）来生成 `window.pywebview` API（`webview/util.py` 的 `get_functions`，跳过以 `_` 开头的属性）。`PlayerWindow` 持有 `self.main_window` / `self.player_window`（pywebview `WebviewWindow` 实例），序列化时会下钻到 `.native`（WinForms CLR 对象）→ `AccessibilityObject.Bounds`（`System.Drawing.Rectangle`）。pythonnet 3.1.0 无法解析 `.Empty` 静态属性而无限递归，冻结 UI 线程。

**修复**: 将 `PlayerWindow` 内的窗口引用重命名为私有属性 `self._main_window` / `self._player_window`（含 `main()` 中的 `player_mgr._main_window = window`），使 pywebview 序列化跳过它们。对外暴露的方法名（`show_main_window`/`open_player_window` 等）保持不变，JS 仍正常调用。

**环境**: pywebview 6.2.1 + pythonnet 3.1.0 + clr-loader 0.3.1（见 uv.lock）。
