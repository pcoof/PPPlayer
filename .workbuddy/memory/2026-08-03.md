- **边缘拖拽缩放失效根因**：`main.py` 的 `_subclass_wndproc` 调用 `GetWindowLongPtrW/SetWindowLongPtrW/CallWindowProcW` 时**未声明 `restype`**，ctypes 在 64 位下默认按 32 位 `int` 返回，原始窗口过程指针被截断 → `CallWindowProcW` 转发失败，WM_NCHITTEST 虽返回命中码但后续缩放消息链断裂，无法真正缩放（最大化保留任务栏的 WM_GETMINMAXINFO 同理失效）。

## 追加：最大化变全屏 + 布局重构（2026-08-03 晚第二轮）
- **最大化变全屏根因**：pywebview winforms `maximize()` 只做 `self.WindowState = FormWindowState.Maximized`。frameless（FormBorderStyle.None）窗口一旦 Maximized 会铺满整屏（含任务栏），WM_GETMINMAXINFO 子类方案太脆弱（依赖子类是否成功安装），故改为**确定性手动方案**：
  - 重写 `toggle_maximize_window`：用 `WinForms.Screen.FromHandle(native.Handle).WorkingArea` 取工作区，手动 `w.move/resize` 贴合工作区（保留任务栏）；用 `_is_maximized` 标志 + `_restore_geom` 保存/还原几何。不再调用 `w.maximize()`。move/resize 与 x/y/width/height 同走逻辑像素，DPI 安全。主/播放窗口共用此方法。
- **布局重构（消除"菜单/列表全宽、滚动错位"）**：
  - 删除全局 `.ts-main { max-width:1640px; margin:0 auto }`（它同时套在头部内层/分类导航内层/正文三个语义不同的容器上，互相冲突）。
  - 新增统一容器 `.ts-container`（max-width 取 `--content-max:1640px`、左右 padding 20px、居中、box-sizing:border-box）与 `.ts-content`（主内容滚动区：flex:1; min-height:0; overflow-y:auto）。
  - `index.html` 三处内层容器由 `ts-main` 改为 `ts-container`；`<main>` 改为 `flex-1 ts-container ts-content py-7`。
  - `body` 改为纵向 flex 外壳（`display:flex;flex-direction:column;height:100vh;overflow:hidden`），`.ts-header`/`.ts-catnav` 加 `flex:0 0 auto` → 标题栏/导航固定、仅主内容内部滚动（替代整页滚动，解决"滚动条只在主内容"）。
  - 窗口控制按钮仍 `position:absolute` 相对全宽 `.ts-toprow`，保持在真实窗口右上角；头部 `.ts-container` 预留 `padding-right:132px` 避免与控件重叠。
  - `--content-max` 放进 `:root`，调宽度只改一处。
- 验证：`py_compile` 通过；Flask 冒烟 `/`、`/player`、`/static/css/style.css`、`/static/tailwind.css` 均 200；HTML 含 3 处 ts-container + ts-content；CSS 含 `.ts-container/.ts-content/--content-max/flex-direction:column`。

## 追加：播放器崩溃 + 自动加载 + 拖拽卡顿（2026-08-03 第三轮）
- **播放器整体崩溃根因**：`static/vendor/xgplayer/index.min.js` 只有 **20670 字节（被截断的残品）**，CDN 真实大小 297057 字节。浏览器解析半成品文件报 `Unexpected end of input`，`window.Player` 从未定义 → hls 插件 `BasePlugin` 读 undefined、XGPlayer 报 `Player is not a constructor`，整页播放器全挂。
  - 修复：重新 `curl -sL` 下载完整 `index.min.js`（现 297057B，尾部含 `Player=` 全局导出）。其余 vendor（hls 260194 / swiper 154597 / swiper-css 18454）均与 CDN 一致、未损坏；alpine 44659 略小于 CDN 最新版但已正常初始化，保留。
  - player.html 内联 JS 经 node --check 通过，无语法错误（之前的 SyntaxError 就是那个被截断的基础库文件，不是业务代码）。
- **列表滚动到底自动加载失效根因**：布局重构后 `body{overflow:hidden}`，滚动发生在 `.ts-content` 内部容器；但 `app.js` 的 `setupAutoLoad` 用 `IntersectionObserver` 默认 root（视口），哨兵 `#loadSentinel`（在 `.ts-content` 内）永远碰不到视口 → 自动加载不触发。
  - 修复：`setupAutoLoad` 的 observer 显式传 `root: document.querySelector('.ts-content')`；`.ts-content` 已是 `overflow-y:auto` 滚动容器，现在哨兵进入视口内 200px 即触发 `loadMore()`。`autoLoadMore` 默认 true，手动"加载更多"按钮在其为 true 时隐藏（无需点击）。
- **拖拽窗口不顺畅根因**：app.js / player.html 的 mousemove 每次都直接发一个未节流的 `api.drag_move` pywebview IPC 调用，事件洪泛 + 每次 `drag_move` 都重查 `active_window()` 一次额外 IPC → 卡顿。
  - 修复（双端一致）：mousemove 改 **rAF 合帧**——每帧只排一次、帧内只发送最新累计位移；main.py `drag_start` 缓存窗口引用 `self._drag_window`，`drag_move` 直接用缓存、不再每次 `active_window()` 查询。拖拽跟手度显著提升。
- 验证：`py_compile main.py` 通过；`node --check` app.js 与 player 内联 JS 均 OK；Flask 冒烟 `/player`、新基础库(297057B)、hls、app.js、style.css 均 200；player.html / index.html 已无 cdn/fonts 引用；`.ts-content` 为 `overflow-y:auto` 滚动容器。GUI 拖拽手感与播放器渲染仍依赖本地实测（无显示环境）。
