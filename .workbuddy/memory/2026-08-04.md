# 2026-08-04 工作日志

## 窗口拖拽/缩放重构（根因修复）
- **拖拽抖动 + 边缘缩放失效**：原方案用 JS 每帧发 `drag_move(dx,dy)` 做指针拖拽（坐标空间不一致→抖动），
  边缘缩放依赖 `WM_NCHITTEST` 子类化（64 位 ctypes 指针/安装时机脆弱→失效）。
- **改为原生方案**：主/播窗口都在标题栏/边缘 mousedown 时调用 `main.py` 的 `start_native_drag(hit)`，
  由 Python 读取 `GetCursorPos` 并 `SendMessage(WM_NCLBUTTONDOWN=0xA1, hit, lParam)` 交给 OS 原生接管——
  hit: 2=HTCAPTION(拖拽) / 10-17=边缘/四角(缩放)。OS 接管鼠标 → 零抖动、边缘缩放 100% 可靠。
- 已彻底移除 `drag_start`/`drag_move`/`_subclass_wndproc`/`_install_window_chrome` 及两处 `events.shown` 安装调用。
- 边缘热区：index.html 与 player.html 各加 8 个 `.win-edge` 固定 6px 热区（CSS 在 style.css / player 内联 `<style>`），
  JS 绑定 `start_native_drag(data-hit)`。窗口控制按钮 z-index 提到 70 高于边缘(60)，避免角区遮挡按钮。
- `main.py` `toggle_maximize_window` 保留：手动贴合 WorkingArea（留任务栏，非全屏）。

## 拖拽/缩放彻底重写为 pywebview 公共 API 驱动（修复"无法拖动/无法缩放边缘"）
- **根因**（之前"原生 WM_NCLBUTTONDOWN"方案根本不可行）：
  1. frameless 窗口 `FormBorderStyle=None`（pywebview 设定，无 WS_THICKFRAME），`HTLEFT/RIGHT/TOP/...` 边缘命中码对 DefWindowProc 是 no-op → 边缘缩放永远不生效；
  2. `start_native_drag` 调 `user32.SendMessageW` 未声明 ctypes `argtypes`，64 位 `hwnd` 被按 32 位 `c_int` 截断 → 消息发错句柄，拖拽也无效。
  （`window.native` 本身是顶层 Form、HWND 正确，问题不在句柄获取。）
- **新方案**：新增 `static/js/window-chrome.js`（主/播窗口共用）。标题栏 mousedown → `drag_move_to(x,y)`；`.win-edge` mousedown → `resize_move(x,y,w,h)`。
  - 以"按下时窗口几何 + 鼠标起点"为锚点算绝对目标（非累加，无抖动）；`requestAnimationFrame` 合并同帧 mousemove + `inFlight` 守卫保证仅一个 IPC 在途，杜绝积压卡顿。
  - Python `resize_move` 按窗口类型强制最小尺寸（播放窗 360×640、主窗 800×600，`_min_size` 用 `native.Handle` 比对 `_player_window`）。
- **改动文件**：`main.py`（删 `start_native_drag`，加 `drag_move_to`/`resize_move`/`_min_size`）；新增 `static/js/window-chrome.js`；`index.html`（引脚本、删旧 inline 边缘脚本）；`app.js` `titleBarMouseDown` 改调 `WindowChrome.startTitleDrag`；`player.html`（引脚本、IIFE 只留标题栏拖拽+双击最大化，边缘交给 window-chrome.js 自动绑定）。
- 校验：`py_compile main.py` OK；`node --check` window-chrome.js / app.js / player 内联 JS 均 OK；全仓已无 `start_native_drag`/`drag_move_native` 残留引用。
- 无图形环境，拖拽/缩放手感需本地实测。
