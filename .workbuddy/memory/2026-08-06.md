## 重构拖拽/缩放：坐标运算移到 Python 端（修复"无法移动/无法缩放"回归）
- **问题**：上一版（带 Aero Snap 的 window-chrome.js）连移动和缩放都失效。怀疑根因：JS 端 `inFlight`/`rAF` 节流死锁、`get_window_rect()` 回退、Aero Snap zone 判定干扰自由移动，以及坐标系换算脆弱——无 GUI 环境无法定位，需更稳架构。
- **根因确认**：pywebview `frameless=True` 把 `FormBorderStyle` 设为 `None`（连标题栏区域都移除），所以 `WM_NCLBUTTONDOWN`(含 HTCAPTION) 在任何 frameless 窗口上都是 no-op；原生方案彻底不可行，只能走 pywebview 的 `move()/resize()` 公共 API。
- **重构**：
  - `main.py` 新增 `JsApi` 类（每窗口独立实例）；坐标运算全在 Python：以「按下瞬间 `w.x/w.y` + 光标 screenX/screenY 位移增量」算目标几何并 `w.move/w.resize`；`resize_to` 按窗口类型强制最小尺寸（播放窗 360×640、主窗 800×600）。
  - `open_player_window` 改为给播放窗新建 `JsApi(self,'player')` 并 `attach`；主窗 `main()` 用 `main_api=JsApi(...,'main')`。消除多窗口共用一个 js_api 的状态/目标串扰。
  - `window-chrome.js` 改为"薄转发层"：仅把 `e.screenX/e.screenY` 经 `drag_start/drag_to/resize_start/resize_to/drag_end` 发给 Python；`requestAnimationFrame` 合并同帧 mousemove（无 inFlight 锁）。移除全部 Aero Snap / 坐标系换算 / `get_window_rect` 前端依赖。
  - 暴露 API：`drag_start/drag_to/resize_start/resize_to/drag_end/get_window_rect/minimize_window/toggle_maximize_window/close_window/show_main_window/open_player_window/close_player/resize_to_aspect`。
- **校验**：`py_compile main.py`、`node --check`（window-chrome.js/app.js/player.html 内联）均通过；用 mock 窗口做了坐标运算单测（移动、八向缩放、最小尺寸保护、最大化拦截）全部 PASS。
- **说明**：为求稳定，Aero Snap（拖到顶/左/右吸附、最大化拖出还原）本轮**未实现**，仅保留双击标题栏/最大化按钮的最大化⇄还原。如需要可后续在 Python 端 `drag_to` 内按 `Screen` 工作区判定实现，风险更低。
- 待本地实测：主窗/播放窗标题栏拖拽移动、八向边缘缩放跟手、最小尺寸生效、最大化⇄还原、最大化时边缘不缩放。

## Aero Snap 已加回（贴边吸附，对齐 Win 原生）
- **诉求**：用户要求"移到屏幕边缘触发 Win 桌面位置"（之前为求稳定把 Aero Snap 拿掉了）。
- **实现**：判定放在 Python 端 `drag_to`（最稳，能与工作区一致）：
  - 新增 `JsApi._screen_working_area(sx,sy)`：`Screen.FromPoint(光标)` 取光标所在屏的 `WorkingArea`（排除任务栏），返回 `{x,y,width,height}`。
  - `drag_to` 内做 zone 判定：`sy<=顶+T`→`max` 最大化；`sx<=左缘+T`→`left` 贴左半屏；`sx>=右缘-T`→`right` 贴右半屏（`T=16` 逻辑像素）。
  - 进入吸附区记录 `pre_geom`（自由几何）；区内直接 `move/resize` 到吸附几何；离开吸附区还原 `pre_geom` 并重置锚点使继续拖拽平滑；`drag_end` 在 `max` 区释放→提交 `_is_maximized=True`、否则解除。
  - 从最大化窗口拖出：`drag_start` 先还原 `_restore_geom` 再跟随光标。
- **顺手修复 `toggleMaximize` 逻辑 bug**：旧版传「当前态」给 `toggle_maximize_window` 导致双击标题栏/最大化按钮失效；改为传「目标态=!maximized」。`drag_end` 返回 `bool(_is_maximized)`，JS 经 Promise 回写 `WindowChrome.setMaximized`，确保最大化后边缘缩放仍被正确禁用。
- **校验**：`py_compile main.py`、`node --check` 均通过；用 mock 窗口做了 Aero Snap 坐标运算单测（顶/左/右吸附、从最大化拖出还原、离边还原、提交最大化）全部 PASS（两处断言本是我测试预期写错，非代码问题）。
- 待本地实测：拖到屏幕顶/左/右三向吸附与离开还原、从最大化拖出还原手感。

## 修复「最大化后点一下标题栏就还原」（2026-08-06 深夜）
- **用户反馈**：每次说找到根因都没改好；本轮具体现象——最大化后点击标题栏任意位置就还原。
- **根因（真 bug）**：上一版的「从最大化拖出还原」逻辑写在 `drag_start`（即 `mousedown` 瞬间）里，所以只要按下鼠标（哪怕只是单击）就立刻还原窗口；`drag_end` 的 else 分支还会在 `self._is_maximized` 为真时无条件置 False，导致单击也解除最大化。
- **修复**：
  - `drag_start` 不再还原，只记录 `was_max` 与 `maxGeom`。
  - 还原动作移到 `drag_to`：仅当「光标位移超过 4px 阈值」才还原 `_restore_geom` 并让光标保持在标题栏同相对位置跟随（对齐 Win 原生：单击不还原、拖动才还原）。
  - `drag_end` 改为只有「本次拖拽确实 `_restored`」才清除 `_is_maximized`；单击（无位移）保持最大化不变。
  - 新增 `_maxGate`：从最大化拖出后游标可能仍在顶部吸附区，若直接判 `zone='max'` 会瞬间重新最大化（抖动）；拖出时置 True 屏蔽顶部吸附，待游标离开顶部区（`sy>wa.y+T`）才解除屏蔽，之后拖回顶部释放仍可正常重新最大化。
- **校验**：`py_compile main.py`、`node --check` 均通过；用 mock 窗口做了 12 项坐标运算单测（最大化单击保持、拖动还原跟随、顶部区内不重最大化、移出再回顶部释放重新最大化、普通拖拽）全部 PASS。
