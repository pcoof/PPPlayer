## 修复「最大化按钮/双击标题栏需点两次才生效」竞态
- 症状：点右上角最大化/还原按钮要两次；双击标题栏最大化后，还原也要两次。
- 根因：双击 = 两次 mousedown/mouseup + dblclick。每次 mouseup 的 `drag_end()` 返回 Promise，其 `p.then(setMaximized)` 在 **异步** 解析；而 `toggleMaximize` 同步乐观置位。普通单击（无吸附）的 `drag_end` 返回旧 `_is_maximized`，其延迟回调把刚 toggle 的状态覆盖回去，导致 JS/Python 状态错位 → 第一次点击/双击失效、第二次才生效。
- 修复：
  - `main.py` `drag_end`：仅当吸附动作真正改变最大化态时 `changed=True`，返回 `{'maximized':bool,'changed':bool}`（不再每次同步本地状态）。
  - `main.py` `toggle_maximize_window`：末尾 `return bool(self._is_maximized)`（返回切换后的真实态）。
  - `static/js/window-chrome.js` `onUp`：仅当 `changed` 才 `setMaximized`，杜绝普通单击/双击覆盖。
  - `static/js/window-chrome.js` `toggleMaximize`：以 Python 返回的「真实最大化态」为准更新 `maximized`（兜底用乐观值），不再仅本地乐观置位。
- 影响范围：主窗(index.html @dblclick/@click winMax) 与播放窗(player.html dblclick/winMaxP) 共用同一 window-chrome.js，均修复。Aero Snap 吸附提交仍走 `changed=True` 同步，逻辑不变。
- 验证：node 无头模拟 4 项全 PASS（单选最大化、双击还原不被覆盖、再单选最大化、单选还原）；`py_compile main.py` 通过。本地仍建议实跑验收手感。

## 优化卡片墙自适应布局（2560→竖图10/横图8）
- 旧方案：断点阶梯 `grid-cols-2 ... xxxl:grid-cols-10 / xxxl:grid-cols-6`，且 `xxl:grid-cols-7 xxl:grid-cols-8` 为重复类 bug；横图在 2560 实际仅 6 列（非 8），断点跳跃、不可平滑自适应。
- 新方案：`static/css/style.css` 新增 `.ts-grid-poster` / `.ts-grid-land`，用 `grid-template-columns: repeat(auto-fill, minmax(MIN,1fr))`——竖图 MIN=224px、横图 MIN=280px，gap=1.25rem(20px)；并加 `@media (max-width:560px)` 手机固定 2 列。彻底摆脱断点 class，任意宽度自动适列数。
- `static/index.html` 卡片墙外层 div 的 `:class` 改为 `currentListLayout()==='poster' ? 'ts-grid-poster' : 'ts-grid-land'`（内部 `.ts-card-media` 的 aspect 比例 class 不变）。
- 计算结果（容器 max-width 2560、左右 padding 20）：2560→竖10/横8；1920→竖7/横6；1440→竖5/横4；1280→竖5/横4；768→竖3/横2；≤560→均2。验证脚本 PASS。
- 注：`utilities.css` 中的 `xxl:/xxxl:` 网格工具类现已无引用（仅卡片墙用过），属无害孤儿类，未删除。

## 修复瀑布流「滚动到底不自动加载，只能点按钮」
- 症状：瀑布流模式下滚动到底部不触发加载，必须点 `加载更多` 按钮。
- 根因：保存配置 `data/config.json` 中 `loadMode:"waterfall"` 但 `autoLoadMore:false`。手动按钮 `x-show` 条件为 `!cfg.autoLoadMore`（故按钮可见），而哨兵 `IntersectionObserver` 的触发条件也含 `this.cfg.autoLoadMore`（故 `false` 时永远不触发）。两者互斥 —— 关掉自动加载后既无自动也无开关可重新打开（设置里无 autoLoadMore 控件）。
- 修复（语义归一：瀑布流即无限滚动，不再用独立开关）：
  - `static/js/app.js` `setupAutoLoad`：自动加载条件由 `cfg.autoLoadMore` 改为 `cfg.loadMode==='waterfall'`（仅瀑布流模式挂哨兵 + 滚动监听双保险；上下页模式只显示分页控件，不自动加载）。哨兵 `#loadSentinel` 加了 `height:1px` 保证 IO 命中。
  - 新增滚动监听兜底：在 `.ts-content` 上绑 `scroll` 监听，`scrollTop+clientHeight >= scrollHeight-240` 调用 `loadMore()`；`loading`/`page>=totalPages` 双重防护避免重复加载；切模式/重设时 `removeEventListener` 旧 handler。
  - `static/index.html`：模式切换两个按钮 `@click` 末尾加 `setupAutoLoad()` 立即重挂/拆除观察器；手动按钮 `x-show` 改为 `... && cfg.loadMode==='waterfall'`（作为滚动自动加载的补充兜底，始终可见）。
  - `data/config.json`：`autoLoadMore` 改回 `true`（已并入 loadMode 语义，仅保持与默认一致）。
- 验证：node 无头模拟 8 项全 PASS（哨兵命中、滚到底、顶部不触发、page 模式不挂、切模式重挂/拆除、loading 防护）；`app.js`/`main.py` 语法检查通过。本地需实跑验收滚动手感。
