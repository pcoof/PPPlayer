## 修复 M3U8 智能去广告（此前完全无效）
- 根因：`static/js/player.js` 的 `renderNative`/`renderArt` 直接 `Hls.loadSource(远程 m3u8)`，从不经过 `/api/m3u8`；`smartAdRemove` 配置与整个广告过滤路由都是死代码，且旧的过滤逻辑只做「跳前 N 片 + 关键词」——对本例无效（广告切片无 `/ad/` 关键词、且 `skip=1` 只丢 3s 片头、还保留了 `#EXT-X-DISCONTINUITY`）。
- 重写 `src/parser/m3u8_filter.py`：按 `#EXT-X-DISCONTINUITY` 切段组 → 每段组按切片 URI 的 dirname 归并为「视频源」→ 正片 = 总时长最长的源（阈值 0.5×最长 + 夹心/边缘位置辅助判定），剔除广告切片并丢弃全部 discontinuity，输出干净单源 VOD；单一源原样透传。
- `src/server.py` 的 `/api/m3u8` 读取 `cms_cfg.smartAdRemove`（默认 true）后传给 `filter_m3u8(smart=...)`。
- `player.js` 新增 `fetchFilteredM3u8()`：m3u8 先走 `/api/m3u8` 取过滤后文本→Blob URL→HLS.js（失败回退直连），native 与 ArtPlayer 两条路径都已接通。
- `index.html` 设置中心→基础 新增「智能去广告」开关（`cfg.smartAdRemove`，已加入 `app.js` 的 `defCfg`）。
- 用 5 类样本（片头/片中/片尾广告、无广告透传、双 CDN 正片）验证：广告 0 泄漏、discontinuity 移除、正片全保留。
- 校验：`node --check`(player.js/app.js) 通过；`py_compile`(m3u8_filter.py/server.py) 通过；server 作为包导入 OK。无 GUI，实际去广告观感需本地 pywebview 实测。

## 用户反馈「还是有广告」→ 找到真正根因并修复（第二次）
- **真正根因**：实际看片页是 `static/player.html`（弹出窗口，XGPlayer 竖滑播放），它直接 `url: ep.url` 把原始 m3u8 交给 XGPlayer，**完全绕过过滤**；上轮只改了 `player.js`（主窗 HLS.js）对看片毫无作用。
- **架构改为「浏览器拉取 + 后端只过滤」**：
  - 浏览器 `fetch` 远程 m3u8（带正确 Referer/Cookie，CDN 一般只认浏览器）→ 避免「后端远程拉取被拒」导致静默回退直连、广告照播。
  - 文本 `POST /api/m3u8_prepared`（后端 `filter_m3u8_text()` 过滤+暂存，不远程拉取）→ 返回 `/api/serve_m3u8/<sid>.m3u8`。
  - 播放器加载这个**以 .m3u8 结尾**的本地地址（XGPlayer/HLS.js 据此识别为 HLS；切片已是后端绝对化后的 CDN 地址，浏览器直取）。
  - 弃用 Blob URL 方案：XGPlayer 靠 `.m3u8` 扩展名判定走 HLS，`blob:` 无扩展名→退化原生播放→Chrome 无法播 HLS 黑屏。
- `m3u8_filter.py` 新增 `filter_m3u8_text()`（媒体去广告 / 主播放列表 `_rewrite_master()` 把变体改写为 `/api/m3u8?url=`）与 `filter_m3u8()` 的 master 分支改写（不再服务端递归下变体）。
- `server.py`：删掉一次性的 `/api/filter_m3u8`，改为 `POST /api/m3u8_prepared` + `GET /api/serve_m3u8/<sid>`（内存暂存，不 pop 防 HLS 重试 404）；`/api/m3u8` 保留作 fetch 失败回退。
- `player.html` 的 `initPlayer()` 改为 `async`，先 `fetchFilteredM3u8(ep.url)` 再建 XGPlayer；`player.js` 的 `fetchFilteredM3u8()` 同步升级为浏览器优先。
- 验证（Flask test_client，无远程拉取）：用户完整样例（9 广告片+30 正片）→ 广告泄漏 0、正片保留 30、discontinuity 0；主播放列表变体正确改写为 `/api/m3u8?url=`；serve 可重复 GET 200。
- 注意：主播放列表场景的变体仍由后端远程拉取（仅该场景依赖 CDN 服务端可达）；媒体播放列表（用户本例）完全浏览器拉取，最稳。

## 用户贴出真实请求链 → 发现「变体被包两层 /api/m3u8」并修复（第三次）
- 用户 trace（对 `2605.fhbbff.com/.../index.m3u8`）：步骤2 `/api/m3u8` 返回单层包装 master；步骤3 POST `/api/m3u8_prepared`；步骤4 serve 返回**双层** `/api/m3u8?url=https://<cdn>/api/m3u8?...`；步骤5 HLS 去拉该地址→后端把 `https://<cdn>/api/m3u8?...` 当 CDN 拉→404→报错/退化直连。
- **根因**：浏览器 `fetch` 远程 m3u8 失败（CORS）→ `fetchFilteredM3u8` 先回退 `/api/m3u8`（单层包装 master）→ 又把这份已包装文本 POST 给 `/api/m3u8_prepared`，`_rewrite_master` 对 `/api/m3u8?url=...` 误判为相对路径、`urljoin(base_url,...)` 拼到 CDN 主机→再包一层。
- **修复**：(1)`_rewrite_master()` 幂等——变体行已含 `/api/m3u8` 则保持原样；(2)`fetchFilteredM3u8()` 回退路径直接返回 `/api/m3u8?url=<原始>` 单层代理地址，不再二次 POST；(3) 两处 catch 不再退化回原始带广告直链（最坏黑屏而非广告）。
- 验证（Flask test_client + mock）：幂等 PASS；回退路径/ prepared 路径均单层包装；媒体列表过滤广告 0 泄漏、正片 30 全保留、discontinuity 0。`node --check` 与 `py_compile` 通过。
