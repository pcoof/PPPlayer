## 分页 + 自动加载同时失效修复（根因：totalPages 单一依赖）
- 现象：用户报告「分页和自动加载都失效，分页模式也不显示按钮」。两模式唯一共同交点 = `totalPages`：分页按钮要求 `totalPages>1`、自动加载要求 `page<totalPages`。后端 apple_cms/feifei_cms/haiyang_cms 均正确返回 `pagecount`，但定制/修改版 CMS 常在 videolist 响应里不返回 `pagecount`（或放别的键），前端 `Number(... || 1)` 兜底成 1 → 两模式同时卡死。
- `app.js` `loadData()` 改为区分「后端真实返回 pagecount」(`rawPageCount != null`) 与「字段缺失被兜底成 1」：
  - 本页空 → hasMore=false；真实 pagecount 且 > 当前页 → hasMore=true；真实 pagecount 且已到末页 → hasMore=false；
  - **pagecount 缺失/不可信 → 以「本页有返回」乐观续载（hasMore=true、totalPages=page+1），遇到空页才停**。彻底解除对单字段的依赖。
- 新增 `hasMore` 状态字段（默认 true）。
- `setupAutoLoad()` 加固：同时监听 `.ts-content` 与 window 滚动（自动选对滚动宿主），`requestAnimationFrame` 节流，终止条件改 `!hasMore`（替代 `page>=totalPages`）；保留初始补加载与 IntersectionObserver 兜底。
- `loadMore()` 守卫重排：先判 `loading || !hasMore` 再设节流，避免守卫返回仍阻塞 250ms。
- `index.html` 自动加载「加载更多」按钮 `x-show` 改 `hasMore`（替代 `page<totalPages`）。分页 `x-show` 仍 `totalPages>1`（乐观扩展后正常显示）。
- 校验：node --check app.js OK；CSS 括号 390/390；hasMore 分支 node 模拟 6 场景全部正确（可靠中页/末页、缺失pc首/次页/空页、显式1页）。

## 点击卡片「无播放地址」根因与修复（23:41）
- 现象：列表能出卡片、点击卡片弹"无播放地址"（alert 来自 app.js openPlayer/openPopoutPlayer 中 parsePlayGroups 返回空）。
- 根因：用户启用源 `caiji.dyttzyapi.com/api.php/provide/vod/at/xml`（URL 含 /xml）被 detector 分派给 FeifeiCMS 适配器；但真实返回是**苹果CMS 的 XML 格式**，播放地址在 `<dl><dd flag="线路">名称$地址#...</dd></dl>` 结构里。原 FeifeiCMS._parse_video_element 只从 `<playurl>`/`<url>` 标签读，根本读不到 → vod_play_url 恒空 → 前端 parsePlayGroups 空 → 报警。
- 修复：`src/cms/feifei_cms.py` 新增 `_parse_play()`：优先解析 `<dl>`（遍历 dd，flag 作线路名、dd.text 作该源地址块，各源以 `$$$` 连接），无 `<dl>` 时回退原 `<playfrom>`/`<playurl>`/`<url>` 逻辑（兼容真实飞飞源）。
- 验证：真实 XML 经 Flask test_client 打 /api/cms/videos → list[0].vod_play_from='dytt$$$dyttm3u8'、vod_play_url 含正确 `名称$地址`；前端 parsePlayGroups 可解析出 2 个有效播放组。py_compile OK。
- 注意：AppleCMS 适配器只处理 JSON（resp.json），不碰 XML；本源走 FeifeiCMS 修复即可。
