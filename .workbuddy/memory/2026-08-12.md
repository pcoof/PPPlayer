## 设置中心「编辑其他源不刷新当前」修复（09:28）
- 现象：在设置中心编辑/新增 API 源时，无论改的是不是当前激活源，`saveSource()` 都会 `loadClasses().then(loadData)` 刷新主视图，打断当前浏览。
- 修复：`static/js/app.js` 的 `saveSource()` 改为条件刷新——仅当「保存的就是当前激活源」(编辑已启用源) 或「新增后成为首个激活源」(`hadEnabledBefore` 为假) 时才 `page=1; loadClasses().then(loadData)`；编辑/新增其它非激活源只 `saveSources()` 静默保存。
- 行为边界：`setActiveSource`（显式切换源）与 `deleteSource`（删激活源）仍会刷新——属合理预期，未改动。importSources 批量导入仍刷新。
- 校验：node --check app.js OK。

## CMS 源「按地址识别类型/补路径不可靠」修复（13:07）
- 现象：用户反馈 `taopianapi.com/cjapi/mc10/vod/json.html` 已是完整 JSON 接口，代码却按地址猜类型并强行补 `/api.php/provide/vod/` → `...json.html/api.php/provide/vod/` 错误地址；`/api/json.php`、`/api/xml.php`、`/api/json` 等"已是完整端点"的源也被错误拼接，取不到数据。根因：apple_cms/haiyang_cms 在 URL 不含 `/api.php/provide/vod` 时硬补该路径；detector 靠 `/xml`、`/api.php/provide/vod` 子串猜 Apple/Feifei 类型，不可靠。
- 方案：新增 `src/cms/endpoint.py`：
  - `resolve_endpoint(base_url)`：仅当"看起来是站点根"（非 provide/vod、非脚本/端点后缀 php/html/json/xml 等、末段非已知端点词）时才补 `/api.php/provide/vod/`；否则原样返回（已是完整端点）。
  - `detect_format(base_url)`：真正拉一次 `?ac=videolist` 看返回是 JSON 还是 XML 来决定类型；按源地址做**模块级缓存**（server 每次请求都新建适配器实例，缓存必须放模块级才有效），站点根额外把 `/xml/` 作为飞飞 XML 兜底候选。
- 改造：apple_cms/feifei_cms/haiyang_cms 的 _request/_request_xml/_detect_interface 全部改用 resolve_endpoint/detect_format；detector.detect_cms 统一返回内容探测适配器（不再按地址猜）。
- 实测（真实网络 + Flask 测试客户端）：taopianapi(json.html)→30条/pagecount3223/带m3u8；xrbsp api/json.php→20条；gdlsp api/xml.php→20条(xml)；dyttzy .../at/xml 回归正常(无播放地址修复保留)；classes 30 类正常。
- 文档：index.html 源地址 hint + README「CMS 源配置」改为说明"填完整接口地址即可，系统按返回内容自动识别 JSON/XML"。
- 校验：py_compile 全部通过。
- 注意：`example.com` 这类纯站点根会补 `/api.php/provide/vod/` 并默认 JSON；若某源是飞飞且只在 `/xml/` 暴露，detect_format 的 `/xml/` 兜底能命中。

## 播放页：进度条左键拖动失效 + 原生全屏（14:31）
- **进度条左键拖动无效、右键有效**：根因是播放页的竖向 Swiper 把主键(左键)按下当作滑动手势抢占指针事件，XGPlayer 进度条收不到 move 事件故无法拖动；右键不被 Swiper 识别故正常。修复：player.html `initPlayer` 里新增 `markNoSwiping(wrapEl)`，给 `.xgplayer-controls/.xgplayer-progress/.xgplayer-volume/.xgplayer-slider` 等控件区加 Swiper 的 `swiper-no-swiping` 类（Swiper 默认 noSwiping:true、noSwipingClass:'swiper-no-swiping'，配置未覆盖），使左键拖动不再触发 Swiper、交给 XGPlayer；视频区仍可竖向滑动切集。找不到控件时 300ms 重试兜底。
- **WebView2 不支持 DOM requestFullscreen**：XGPlayer 原生全屏按钮无效。修复：
  - `main.py` 的 `JsApi` 新增 `toggle_fullscreen()`，调用 pywebview 窗口原生 `w.toggle_fullscreen()`（OS 级真正显示器全屏，覆盖任务栏）。
  - player.html 移除 XGPlayer `ignores:['fullscreen']`（恢复自带全屏按钮），并 `player.on('fullscreen')` 拦截：先 `document.exitFullscreen()` 退出浏览器自带全屏，再 `window.pywebview.api.toggle_fullscreen()` 走 Python 原生全屏；双击视频也会触发（XGPlayer 双击全屏）。
  - 顶栏窗口控制新增「全屏/退出全屏」按钮 `winFullscreenP()`，直接调 `toggle_fullscreen()`，作为始终可见的可靠入口。
- 校验：内联 JS 经提取后 `node --check` 通过；`main.py` py_compile 通过。
- 注意：若用户先点 XGPlayer 全屏按钮进入 Python 全屏后又按 ESC 退出 OS 全屏，XGPlayer 内部态未同步（少见边界），再点一次按钮即可纠正。

## 自动加载"未滚到底也加载"修复（15:54）
- 现象：自动加载模式滚动到一半甚至停在顶部就连续触发 `loadMore()`，没有滚到底。
- 根因：`setupAutoLoad()` 原 `nearBottomWindow()` 用 `window.scrollY >= documentElement.scrollHeight - 300` 判定，但本布局由内层 `.ts-content`（`overflow-y:auto`）承载滚动，**窗口本身不滚动**→`scrollY` 恒为 0、`documentElement.scrollHeight`≈视口高→条件永远为真；原代码 `nearBottomContent() || nearBottomWindow()` 于是无条件触发。
- 修复：新增 `activeScrollHost()`——仅当 `.ts-content` 实际可滚动（`scrollHeight-clientHeight>4`）才用它判定，否则退化 `window`；统一 `nearBottom(host)` 按宿主计算；去掉无条件双 OR；`IntersectionObserver` 的 root 设为真正的滚动容器（content 或 null），保证内层滚动时哨兵进入视口才触发。
- 校验：node --check app.js OK。本机实测：滚到底（距底 300px）才加载，停顶部不自动加载。
